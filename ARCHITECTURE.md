# Architecture

The [design book](https://claude.ai/artifact/A3KR8SWWJouwinJsSZUje8) defines the crate boundaries. Before adding a crate or module, document what it owns and what it must not do. Define interfaces at their call sites and record constraints on thread, blocking, and call order when those interfaces exist.

## Crates and allowed dependencies

Edges in the last column go from the row's crate to the listed crates. They are permissions, not dependencies to declare before use. The P3 packages are listed for reference and are not workspace members.

| Crate | Owns | Must not do | May depend on |
| --- | --- | --- | --- |
| `sumie` (binary) | Composition, CLI parsing, platform traits, config-to-core option conversion, passing font atlases to the renderer | Business logic | All library crates |
| `sumie-core` | Tabs, panes, selections, link and shortcut matching, commands, agent state, plain-data options | Platform code, config, GPU, FFI, unsafe code, blocking I/O | None |
| `sumie-config` | Settings types, loading, validation, hot reload, writing TOML, JSON Schema generation | Manage windows or render | None |
| `sumie-vt` | Safe libghostty-vt wrapper | Render, call platform code, match shortcuts | `sumie-core`, `sumie-config` |
| `sumie-font` | Font discovery and fallback, shaping, rasterization, glyph atlas data | Issue GPU calls or read or change terminal state | `sumie-core`, `sumie-config` |
| `sumie-render` | wgpu rendering from atlas data and draw lists | Discover fonts, depend on `sumie-font`, change terminal state, allocate GPU objects per frame, submit GPU work while holding a terminal lock | `sumie-core`, `sumie-config` |
| `sumie-ui` | Drawn tab bar, sidebar, command palette, menus, hints | Make business decisions or call Wayland or AppKit directly | `sumie-core`, `sumie-config`, `sumie-font`, `sumie-render` |
| `sumie-wayland` (Linux) | Wayland connection, windows, input, input methods, clipboard, fractional scaling | Match shortcuts, make business decisions, block the main loop on clipboard reads | `sumie-core`, `sumie-config` |
| `sumie-macos` (macOS) | Windows, input, input methods, clipboard | Match shortcuts, make business decisions, block the main loop on clipboard reads | `sumie-core`, `sumie-config` |
| `sumie-pty` | Shared Unix PTY, child processes, reader threads | Touch window objects or render | `sumie-core`, `sumie-config` |
| `sumie-ipc` (P3) | Socket protocol and client shared by the CLI and settings TUI | Make business decisions or render | `sumie-core`, `sumie-config` |
| `sumie-settings` (P3) | Settings TUI | Parse or write TOML itself or access GUI state directly | `sumie-config`, `sumie-ipc` |

Two edges are deliberately closed:

- `sumie-render` → `sumie-font`: the font crate produces CPU-side glyph atlas data. The binary passes that data to the renderer, which accepts only atlas data and draw lists.
- `sumie-core` → `sumie-config`: core defines plain-data options. The binary translates parsed TOML settings into those options, so headless core tests and the future daemon do not require TOML.

## Tabbed Linux window

`main` handles the schema and defaults commands without opening a window. The Linux app loads TOML before connecting to Wayland. It maps font settings and environment overrides into `FontSettings`. It configures terminal colors before spawning the PTY, passes selection overrides to the view, and sets the renderer's minimum contrast ratio.

`sumie-config` supplies the built-in Cobalt2 colors and uses the same defaults for JSON Schema and the generated TOML example.

`linux::driver` owns the calloop loop for the Wayland window and calls the platform-neutral `app::frame_steps` on that thread. Each dispatched batch services ready PTYs, then applies the batch's window events in order (`app::window_events`), then retires panes whose child exited. A frame then applies pending geometry, refreshes snapshots and draws at a free frame slot. `app` reaches the window only through `WindowOps`. `pane` owns the local terminal, key encoder and PTY. The consumer calls `Pane::command` and draws from its own `Pane::snapshot` result; neither method waits for PTY I/O. `view` composes the owned snapshot and IME preedit into device-pixel draw lists and hands font atlas data to the renderer. `capture` handles opt-in frame readback and PNG output; normal presentation does not read back pixels.

The binary's `platform` module defines the session's ordered events, `PaneWatches`, and `WindowOps`. `linux` binds those operations to Wayland, creates the GLES display descriptor and converts the caret to surface coordinates. Its readiness registrations in `linux::sources` use stable pane IDs; the session owns the PTYs and decides when to drain, flush or reap them. `app::lifetime` services closing children even after the last tab and GPU are gone. Neither the renderer nor the session owns native window state.

Platforms report pointer positions as `platform::Position`. Wayland sends `SurfaceLogical`, which `view::geometry` maps by the viewporter ratio between the rounded buffer and its logical size. AppKit backing pixels arrive as `DevicePx` and are used as is. Never convert them through the point extent: at 2× or 1.5× an odd buffer has a fractional point extent, which the view keeps only rounded, and the rounding moves boundary hits.

`sumie-core::WindowTabs` owns tab order. Each tab has a binary split tree with stable pane IDs, one focused leaf and optional pane zoom. `splits::geometry` partitions device pixels. It reserves a cell per leaf and a pixel per divider when space permits, using cell dimensions supplied by the view rather than font or PTY state. `app::tabs` binds the leaves to live PTYs, selections and searches. The Linux window registers descriptors by pane ID. The focused pane owns the tab label, keyboard and IME. `app::directory` resolves local OSC 7 URIs for new tabs and splits without changing the process working directory.

The window uses the same layout for PTY sizing and drawing. Pointer hits must agree with the presented geometry. `view` composes pane-local grids and overlays with a shared font atlas; `sumie-render` clips each grid and image to its own rectangle and presents the window once. Split chrome uses the Astryx palette from `sumie-ui`. The event loop dispatches queued input before retiring exited panes. A focus change drops repeats for held PTY keys, ends reported pointer drags and resets IME composition. A reported key press pairs with a release in its original pane while that pane exists. Pending clipboard reads also stay with their original pane. Directional focus and resize shortcuts reach the PTY only in a single-pane tab. As in Ghostty, a left click that moves pane focus reaches neither the program nor the selection, and neither does its release; other buttons focus and are delivered.

`view::geometry` converts logical padding and pointer positions into device-pixel pane and grid coordinates, and the caret back to surface-logical coordinates, on the event-loop thread. It neither performs I/O nor submits rendering work. Each split reserves the padding plus one cell per leaf when space permits. In smaller panes, padding shrinks before the cell is clipped. The same inset determines PTY dimensions, the draw origin, and pointer coordinates; the pane background fills the padding and any leftover pixels to the right and bottom.

Restoring or activating a visible window releases a stalled frame slot. A press blocked by pending pane geometry also releases the slot, but is not replayed onto the new layout. A late callback from the replaced slot cannot release the new slot. Pane, search and thumbnail hit geometry still advance only after a successful buffer submission.

On Linux, a resize invalidates pointer hits immediately. At the next available frame slot, the app applies the latest configure to all terminal grids, PTYs and the GPU surface before taking snapshots. Intermediate sizes never trigger scrollback reflow.

`sumie-ui::TabLayout` uses 190-logical-pixel tabs when space permits. Under pressure, each tab reserves up to 112 logical pixels for the title, in addition to its number and controls. The visible run stays contiguous and keeps the active tab in view. The new-tab button follows the last visible tab. The active underline spans the content box, inset equally on both sides. The tab bar takes its colors from the focused terminal snapshot. For the active underline, it tries ANSI yellow and then the Astryx accent, requiring 3:1 contrast against the bar. If neither qualifies, it uses the terminal foreground. The renderer draws the strip, shadow, geometric controls and labels after the terminal. Labels use a separate atlas from the grid. `python3 scripts/astryx-tokens.py` generates the checked-in chrome tokens. Only a presented layout supplies click targets, including the hovered tab's close button. A background tab records activity only when a PTY batch changes a pane's visible screen contents and at least 300 ms have elapsed since that pane's last resize.

`sumie-config` keeps cursor and image settings in private `cursor` and `images` modules. They supply defaults and merge included settings; the VT and renderer apply them.

`sumie-config::window` validates the default background opacity and resolves window settings across includes. On Linux the app applies opacity and blur together before presenting the next frame; neither setting changes pane geometry.

On Linux, `sumie-config::Watch` registers the primary file, every visited include, and their parent directories before reading. It watches for atomic replacement and follows missing paths from the nearest existing parent. `reload` supplies the watcher descriptor to the Linux adapter and sets a 100 ms deadline after the last relevant notification. Loading TOML and rebuilding a changed font can block the event-loop thread on filesystem I/O; the watcher itself spawns no thread. Failed loads retain the active settings and log a diagnostic once per outstanding error. `view` draws the diagnostic in place of the first terminal row, truncating with an ellipsis and leaving the terminal grid and its contents intact. Repair removes the overlay even when the effective settings did not change; other unchanged saves do not schedule a frame.

The pane sets the scrollback byte limit before PTY spawn. Reload updates the live VT limit and refreshes the viewport and any active search because lowering the limit can prune history.

`login::Environment` is the requester's environment plus the terminal identity, then on macOS the resolved shell and locale (`macos::login`). Each driver resolves it once before its window opens and hands it to the session; `login::Login` is the copy one pane starts, with shell integration when `shell.integration` is on. `login::terminfo` owns the bundled entry and its on-disk cache, not the PTY or VT replies; it compiles with `tic` from `PATH` on Linux and `/usr/bin/tic` on macOS. The first `Environment` or `request_environment` call can block on the cache lock, filesystem access, and `tic`; live-pane methods never call it. The macOS terminal driver calls `macos::login::prepare`, which also installs the shell integration scripts, before the window opens. A missing or stale entry that cannot be compiled falls back to `xterm-256color` without exporting a `TERMINFO` override.

`login::shell_integration` installs embedded startup scripts before spawning a supported login shell. It modifies only the child environment, never the user's shell profiles. zsh reads a `ZDOTDIR` shim that restores the user's `ZDOTDIR`; fish reads `XDG_DATA_DIRS`. On Linux, bash starts in POSIX mode with `ENV` naming `bash/sumie.bash`, which sources the login profiles itself. Apple's bash 3.2 reads `ENV` only when started as `sh`, so on macOS bash starts as a plain login shell and `PROMPT_COMMAND` gains a bootstrap entry, after any the requester set, that runs the hooks after the profiles and is then replaced by a no-op that keeps `$?`, wherever the profiles moved it. A profile that replaces rather than extends `PROMPT_COMMAND` therefore loses integration; a nested bash that inherits the entry without `SUMIE_BASH_SCRIPT`, or a re-exported `PROMPT_COMMAND`, runs nothing of sumie's. The script stays Bash 3.2 compatible: before 4.4 it marks a command from the first DEBUG trap after `PS1` expands (the expansion arms it, so later `PROMPT_COMMAND` entries are not commands), installed at top level because 3.2 hides and restores the DEBUG trap around functions and `.`, and chains the user's DEBUG trap with the same `$?`. A DEBUG trap installed later, such as bash-preexec's at its first prompt, is chained at the next prompt, which reinstalls sumie's in front; the command between the two goes unmarked. User `PROMPT_COMMAND` entries and `PS1` see the command's status. The VT `shell` module reads prompt and working-directory state from the pane's native terminal on its owner thread. It does not interpret the OSC 7 URI as a local path.

PTY readiness clears the wake before draining output into VT. Key commands carry unencoded input; the local pane encodes them with the terminal's current modes. IME preedit only changes the overlay; only commit bytes cross the pane boundary. Input writes remain ordered in the PTY FIFO. Wayland configures the first frame slot. After that, output, geometry or preedit can use a free slot, but a frame callback alone never dirties the view. Close drops GPU state before the Wayland window and drives child reaping from pidfd readiness and the PTY close deadline.

One calloop timer advances the cursor's 600 ms blink phase when the focused viewport permits blinking. Key presses and PTY output restart the visible phase. Steady, off-viewport, VT-hidden, and unfocused cursors have no blink timer, nor do suspended toplevels. A cursor config reload resolves the effective blink mode before waiting for another frame callback. A phase change can present the cached draw list without reshaping the grid. The text-input caret rectangle tracks the terminal cell independently of the drawn cursor.

Both platforms share one application shortcut table, `sumie_core::Shortcuts`, owned by the core `shortcuts` module: it matches a key before encoding and reports the action, and never runs one or touches a PTY. The binary passes `platform::POLICY` (`sumie_core::Platform`), which picks the primary modifier. On Linux it is Ctrl+Shift for letters and Ctrl for zoom, Alt+digit selects tabs, and Super never matches. On macOS Command takes both roles (Cmd+C/V, T/W, E/O, F, Z, =/−/0, 1–9, and Cmd+Arrow for pane focus in a split tab) and is matched by named physical position first, then by the layout's character. Every Command chord and the Command keys themselves are consumed whether or not an action runs, and so are the repeats a key held before Command makes while Command is down, so none reaches a PTY or the search box; that key's release still does. Quit and Hide stay `AppKit` key equivalents and Cmd+\` window cycling stays `AppKit`'s, so none of them reaches the table; winit's menu has no Minimize item, so Cmd+M does nothing. Option is not a shortcut modifier on macOS, so the Alt+digit aliases cannot take a right-Option character. Both platforms share Ctrl+Tab and Ctrl+PageUp/PageDown for tabs, Ctrl+Alt+Arrow (Shift to resize) for panes in a split tab, which reaches the program in a single-pane tab, and Shift+PageUp/PageDown. A matched press owns its repeats and release. On Linux, letter shortcuts follow the keyboard layout. `linux::events` converts evdev positions and XKB symbols before routing. Core matches named physical positions for non-Latin layouts; unidentified keys retain distinct press and release identities. The Wayland `clipboard` module reads the keyboard seat's selection on a nonblocking calloop pipe. It delivers non-empty UTF-8 reads in request order and releases the slots of failed reads. Reaching the size limit closes the pipe without delivering a partial paste. A read carries the input recipient's generation from the paste request. The app discards stale replies and delivers current ones to the query or to `PaneCommand::Paste`. In mode 2004, the VT wrapper removes embedded bracketed-paste end markers. In either mode, it strips control characters other than Tab, LF, and CR before calling `ghostty_paste_encode`. The pane enqueues the encoded paste in one operation, including both markers when mode 2004 is active. Clipboard warnings never include clipboard text.

On Linux, core matches the zoom chords by keysym before PTY encoding. The window's `View` holds the zoom separately from configured font settings and preserves it across display scale changes. Zoom and font reload replace the terminal font and atlas, then resize the VT and PTY grid in every tab without resizing the surface. A font reload clears the zoom. A fresh font atlas starts fully dirty even when the GPU texture dimensions do not change.

The core `selection` module tracks inclusive ranges relative to the viewport, including endpoints outside it when a word or logical line wraps. It includes both cells of a wide glyph and does not read terminal text. The GUI maps surface coordinates to grid cells, inverts the selected cell colors unless overridden, and splits shaping runs at selection and foreground color boundaries. On release or a copy shortcut, the pane resolves the range with the VT plain-text formatter; neither command writes to the PTY. The Wayland `clipboard` module serves the resulting immutable text through nonblocking calloop writes. Read and write pipes have a five-second deadline. Replacing, clearing, or losing ownership of the selection cancels writes for the old source. The adapter does not publish a primary selection.

Terminal clipboard writes reuse this data source on the main thread. The adapter uses the keyboard seat's last focus or input serial and discards the request without keyboard focus. A terminal can write or clear the standard clipboard. A user copy uses the serial of its originating key press or pointer release, only while that event is being handled. The app stages the latest terminal title, and Wayland applies it just before the next frame commit.

The GUI clears the selection on resize or when output changes the selected text or removes an endpoint. It compares the formatted text, including rows outside the viewport, against the text captured when the range changed. Clearing the range does not give an active selection drag to the PTY. Before starting a gesture or resolving a copy, the GUI refreshes a dirty snapshot.
The Wayland pointer adapter forwards seat events, press timestamps, and modifiers without routing them. At startup it reads the KDE or GNOME double-click interval when available. KDE defaults to 400 ms; the core uses 500 ms when no desktop setting is available. The core `mouse` module counts presses while the pointer stays in the same cell and modifiers stay unchanged. It owns gesture routing and wheel remainders, by the same `Platform` policy as the shortcut table. On Linux, Shift starts a selection under mouse tracking and a drag release copies (`SelectStep::Finish { copy: true }`). On macOS a drag selects whole cell groups and its release does not copy; only Cmd+C writes the pasteboard, and there is no primary selection. Under mouse tracking a left press is held back: leaving its cell, which includes the padding a clamped position shares with an edge cell, turns it into a selection from the press cell and reports nothing; releasing in its cell reports the original press and the release together (`Dispatch::Click`); another button's press drops it. Option+drag goes to the program at once, without Option in the reports; other buttons and hover are reported as on Linux. `sumie-macos` forwards winit's vertical scrolling unconverted; `macos::window` converts lines (a notch each) or backing pixels (a notch per ten points) to value120 once, keeping fractions for the core's remainder, which then routes to mouse tracking, alternate scroll or the history like a Wayland axis. On the pane thread, `pane::mouse` applies that decision using the live modes. The VT `mouse` module owns the native mouse encoder and viewport bindings.

`app::links` caches the URI and sorted cell ranges at the pointer. Plain URL detection only visits the hovered logical line and reuses its cached match within the range unless the hit could resolve to OSC 8. Before a snapshot consumes Ghostty's dirty flags, the tab checks the identity and damage of the rows the lookup depends on. Drawing walks the cached ranges in grid order. Where no SGR underline is set, the view draws dotted hints on OSC 8 cells and hovered plain URLs, or a solid foreground hint on Ctrl hover. A left press with the platform's link modifier (Ctrl on Linux, Command on macOS) captures a link ahead of PTY mouse tracking; release opens the same validated URI only if the gesture did not become a selection drag, so dragging off the link cancels even after the pointer returns. On macOS the press holds while the pointer moves along its link, so the release opens it wherever on that link it lands; on Linux any motion cancels the open. The link hint and hand pointer follow the same modifier. In a `macos-ci` build run by the runner, the opener is a stub that prints `runner opened` and the URI's length. The Wayland adapter applies the cursor using the current enter serial and falls back to the Xcursor theme when cursor-shape-v1 is absent. `sumie-pty::open_url` spawns and reaps the desktop opener outside the event loop, without a shell, inherited nonstandard descriptors, or logging the URI.

On Linux the worker starts `/proc/self/exe --internal-link-opener URI` with null stdio. Before starting threads, that process revalidates the URI, closes its own descriptors above 2 using `/proc/self/fd`, and calls `execv` on `xdg-open`. A concurrent PTY creation in the original process cannot change the helper's descriptor table. On macOS, `posix_spawn` uses `POSIX_SPAWN_CLOEXEC_DEFAULT` and explicit file actions for stdio. Neither path requires a Rust `pre_exec` hook in a safe crate.

Shift+PageUp and Shift+PageDown scroll the history by the grid height on the primary screen and reach the program on the alternate screen. Viewport scrolling clears the selection and its drag anchor. Key presses and repeats that produce PTY input return the viewport to the bottom. A key release leaves the viewport and selection unchanged.
After a resize puts the viewport at the bottom, the VT returns to the active area so new output stays visible.

`app::search` drives the query in bounded slices on the terminal owner thread. In-place redraws mark changed active rows without rewinding a scan. After reaching the tail, the matcher repairs changed rows up to the next boundary where neither the old nor the new scan carries a partial match or pending spaces. Scrolling output keeps the unchanged history prefix. A width change can reflow history and requires a fresh scan. The VT `anchor` module owns Ghostty tracked references, not text. Search uses separate anchors for the history boundary and the selected match. A trimmed anchor has no position. Closing search leaves the viewport in place.

`app::highlights` projects matches onto the visible rows as disjoint spans, splitting the selected match from its neighbors. `view::overlays` tints each covered cell once, excluding wide-character wrap spacers, and draws the diagnostic banner and search box. The box overlays the terminal without changing the grid or PTY dimensions. It moves away from the current match when the two overlap. The search caret supplies the IME rectangle even when the terminal cursor is hidden.

VT search reads Ghostty pages one row at a time without moving the viewport. A typed Zig bridge projects searchable cell data into a reusable Rust row buffer. It omits hard-line padding and reads a grapheme cluster only when the cell has one. The matcher uses Unicode simple case folding unless the query contains uppercase. It saves its state at the boundary between history and the active screen so output can invalidate the suffix of a wrapped line without rescanning its immutable prefix. Search retains match coordinates, not a second scrollback.

If surface acquisition times out, reports occlusion, or needs reconfiguration, the app retains the dirty frame and retries on a deadline. An idle or suspended surface has no retry deadline. On macOS a timed-out acquire holds the frame slot instead (see [macOS window](#macos-window)). Runtime font errors leave affected cells blank if no replacement glyph can be drawn; the view logs each error variant once without logging the input text.

`app::frame_log` writes `SUMIE_FRAME_LOG` in every build, including release, so the multi-pane budget is measured on the shipped binary. The session reads the variable once at startup; when it is unset, each hook is one `Option` check per frame and nothing per pane. A presented frame appends one line: `CLOCK_MONOTONIC` nanoseconds when snapshot refresh starts, when snapshots are done, when the draw list is built, when the surface texture is acquired and the GPU work submitted, and when present returns, then the count of dirty visible panes and the IDs of the panes `View::build_pane` repainted rather than reused. Records hold no terminal content. The frame path only appends to a shared buffer; the `sumie-frame-log` thread swaps it out and writes it at most once per second, and the last batch on drop.

For screenshots, `--exit-after-frames N --screenshot PATH` captures the Nth actual presentation. Use changing terminal output or an enabled cursor blink to reach later frames.

The Linux adapter creates the wgpu instance and surface with the native display and window handles. `gpu` passes the surface to `SurfaceRenderer`; it does not own the window or dispatch input. wgpu retains the shared `WindowOwner`; the renderer's GPU resources drop before the surface, and the native window cannot drop while the surface still owns it.

## macOS window

`sumie-macos` owns the winit event loop, creates its window on the main thread when winit resumes, and converts winit events. Pointer positions stay in backing pixels (`Position::DevicePx`). `SUMIE_MACOS_DRIVER=terminal` selects the terminal driver; the Metal test page stays the default. With `--features macos-ci`, `SUMIE_MACOS_CI_RUNNER=terminal` runs the terminal driver under the runner's controller. Both platforms use the binary's `FrameWindow` contract to notify the window system just before presentation.

`sumie-macos::keyboard` maps winit's `KeyCode` to the shared `PhysicalKey`; a position the table does not name keeps its `AppKit` virtual key code as an `Unidentified` identity. The layout's symbol (winit's logical key: Shift applies, Control and Command do not) and the typed text (`NSEvent.characters`, every modifier applied, `AppKit`'s private-use function-key characters removed) stay separate, as on Linux, so the shared table and encoder see the same three inputs. The window sets `OptionAsAlt::OnlyLeft`. Left Option is Meta: winit types the key without it and Alt stays set, so Ghostty's encoder, which the VT wrapper always configures with `macos_option_as_alt = left`, prefixes ESC once. Right Option, and an Option flag without a side bit (winit's `OnlyLeft` keeps its characters too), is the layout's compose key: its characters stay, `KeyModifiers::right_alt` sets Ghostty's Alt side bit, and a printable character it typed marks Alt consumed (`alt_consumed`), so it neither prefixes ESC nor counts as Meta, while right Option on an arrow or Backspace stays Alt. Its dead keys compose through the input method, below. `MacWindow` forwards every key, Command chords included; the shortcut table keeps them out of the PTY. The window reports `Event::KeyboardFocus` only when key status changes; a `ModifiersChanged`, including the empty one winit sends on focus loss, never stands for focus. The shared `Session::keyboard_focus` releases each reported press in the pane that received it, wherever it now is, forgets every held key so late repeats and releases after refocus stay out of the PTY, and reports the change to the focused pane in mode 1004 (`PaneCommand::Focus`, encoded by Ghostty). Wayland does not route its keyboard leave there yet, so Linux keeps its previous behaviour.

The terminal driver lets input methods compose while the window is key; the runner keeps them off unless asked (`ime on`), so its key checks post below the user's input source. winit's preedit and commit reach the shared path that Wayland's text input feeds: preedit only changes the overlay, which underlines the input method's selected clause (Linux passes none and underlines the whole text), and only commit bytes reach the pane. `sumie-macos::ime::Composition` binds a composition to the input generation current at its first non-empty preedit; its preedits, the empty preedit that ends it and its one commit carry that generation, so the session drops them once the recipient changed. A new generation (pane, tab, search or viewer), focus loss or a commit under another input source than the composition began with ends the owner first, so a late commit has none and is dropped; the window then cancels the native marked text (`Platform::cancel_composition`, which disallows and re-allows input methods). winit forwards no key-up while the input method composes, so the first non-empty preedit sends the release of every forwarded press, with the modifiers held then; routing drops the real release if it comes later. The candidate window follows the caret of the last presented frame (`WindowOps::set_cursor_rectangle`), through zoom, scale and focus changes.

`macos::driver` runs the shared `app::frame_steps` on the main thread. Callbacks queue native events in `macos::window::MacWindow`. winit's `about_to_wait`, whose observer is in the common run-loop modes, runs one turn: the batch (ready PTYs, the queued events, retirement), then a frame. `Event::Ready` first folds the readiness bridge's reports. The session's own deadlines (retries, closing children, search) arm one bridge timer. The driver starts the configuration child when the window opens; the session starts from its first result, and later results apply through `App::apply_config`, the hot-reload path Linux uses. A close before the first result needs no session.

`macos::surface` owns the frame slot. It is paced by `NSScreen.maximumFramesPerSecond` of the window's screen, read again after a screen or scale change. A present holds the slot until the next refresh and arms a one-shot bridge timer. A busy window keeps the slot's cadence, so it presents at most once per refresh. An idle window has no timer: the first frame after idle draws at once, and nothing clean presents. A resize or scale change only stores the latest size (`View::request_resize`). At a free slot, pending geometry waits until `device.poll(Poll)` reports an empty queue (`WindowOps::may_configure`); otherwise the slot is held for one refresh, and intermediate sizes are dropped. After a drawable timeout (`WindowOps::hold_after_timeout`), the window holds the slot for 1 s, doubling to 8 s until a present. An occlusion, screen or Space change ends the wait; a Space switch reaches the window as an occlusion change. Refocusing does not: `WindowOps::recover_frame_slot` frees a slot held for pacing but leaves a back-off alone. PTY servicing, Quit and pings continue meanwhile. Because a visibility change ends the wait, the first acquire after it may time out again and block the main thread for about 1 s, once; rule A of the M1b-1 plan (§1.5: every main-thread callback returns within 100 ms) allows exactly this exception. An occluded window does not draw. When it is uncovered, the slot is released and `Event::Exposed` marks the view dirty, so one frame with the latest content presents even if `AppKit` purged the layer's contents (display sleep, a GPU switch); otherwise nothing clean presents.

Close retires every pane, then queues `orderOut:` through `run_after_handler`. After it runs, the driver waits up to 100 ms on the main thread for an empty GPU queue, then drops the renderer, the surface and the window owner, in that order. The loop keeps running without a window until its closing children are reaped through their exit watches. `Open` declares the GPU before the window, so the same order holds if the loop ends with the window open.

The red button, Quit, the last shell's `exit` and a fatal error all drain this way, so the window leaves the screen before any child is reaped. `sumie_macos::run` installs the Quit hook when the loop resumes and delivers each request as `Event::Quit`; when the callback then returns `Break`, it calls `finish_quit`, which grants the re-issued `terminate:` or replies to a system quit. Without a pending request, `Break` ends the loop. `sumie-macos::termination` owns the drain's clock, which starts at the first of these and never resets, its stages (`hiding`, `releasing`, `reaping`, `exiting`, logged with counts and never payloads) and the deadlines. Closing children get SIGHUP, then SIGKILL at the PTY grace period (3 s, which is also the system-quit bound). A system quit, or one that upgrades an ordinary drain, stops reaping 4 s after the drain began, so `AppKit` gets its reply even if a child survives; launchd inherits it. A watchdog thread reads only the hard deadline and atomic stage and count words: 10 s after the start (6 s for a system quit) it logs the open stage and calls `_exit` (`signal-hook`'s safe wrapper; nix 0.31 has none): 0 for a system quit and 70 otherwise, without logging a reap. A fatal error drains like Close, then `run` returns that error without `terminate:`, so `main` prints the original diagnostic and exits 1; a second error while draining ends the loop at once with the first. While a system quit waits for its reply, a fatal error is logged and the reply still goes out, because log out, restart and shut down are never refused. The test page treats Quit as Close.

The macOS test page owns a fixed grid of ASCII, CJK and box-drawing glyphs, not a terminal or PTY. It rebuilds the atlas on scale changes; a size change only reconfigures the surface. In frame-limited mode it requests redraws until the requested presentation, then writes that frame if a screenshot was requested.

The root manifest pins `wgpu-hal` and its path siblings to the reviewed fork listed in `third_party/README.md`. On macOS the fork lets `CAMetalLayer.nextDrawable` time out after about 1 s, so a stalled acquire returns `SurfaceFrame::Timeout` instead of blocking the main thread without bound; the terminal driver then backs off as described above. `sumie-render`'s `metal_layer` test checks the flag after configure from its own test target, so the library keeps `forbid(unsafe_code)`.

winit comes from a pinned fork (`[patch.crates-io]`; diff in `third_party/winit/0001-quit.patch`) that adds three macOS calls and fixes two input-method paths; `sumie-macos` stays free of `unsafe`. Disallowing input methods also discards the input method's own marked text, and Command chords skip the input method, so Cmd+V during a composition reaches the shortcut table instead of being typed as `v`. `run_after_handler` runs a closure once no winit handler is running, through a common-modes `CFRunLoopPerformBlock`, so it also runs in menu tracking, live resize and `NSTerminateLater`'s modal-panel loop. `terminate:`, nested run loops and `orderOut` go through it, never inside a handler. Every macOS loop intercepts Quit. `intercept_quit` turns the first `applicationShouldTerminate:` into a `QuitReason` event. An ordinary Quit is cancelled and later re-issued and granted by `finish_quit`. A quit Apple event with any `keyAEQuitReason` (log out, restart, shut down, or a reason winit does not know) gets `NSTerminateLater`, never `Cancel`, and `finish_quit` replies through `run_after_handler`; one that arrives while an ordinary Quit drains upgrades it. `scripts/macos-spike/quit.sh` builds a fixture from the pinned commit; `check-gate.py macos-quit` covers the menu, key, nested, logout, shutdown, menu-during-later, quit-all, unknown-reason and upgrade cases.

`sumie-macos::readiness` owns the macOS wake source. `Bridge` runs one thread that waits on a close-on-exec kqueue and never calls `AppKit`. That kqueue holds `F_DUPFD_CLOEXEC` duplicates of the PTY wake, input, exit and config-socket descriptors, plus one-shot `EVFILT_TIMER` deadlines. Each registration has a key (pane ID and interest) and its own generation; a report from a removed or replaced generation is dropped. A descriptor reports once (`EV_DISPATCH`) and stays disabled until the main thread re-arms it. The bridge records ready keys and sends one `EventLoopProxy` event per batch the main thread has not taken. `remove` drops the key's untaken report under the bridge lock, but cannot recall a wake already sent for it (a re-armed, still-ready descriptor can report between a take and `unregister`). So the proxy handler delivers a wake only if `Readiness::accept_wake` finds reports left; a refused wake re-enables signalling. Nothing from a removed key surfaces after `remove` returns. winit adds the proxy's run-loop source in common modes, so the wake also arrives during menu tracking, live resize and `NSTerminateLater`'s modal-panel loop. `sumie_macos::run` hands the callback a `Readiness` handle and turns the proxy event into `Event::Ready`. The binary's `macos::sources::Watches` implements `PaneWatches`, `ExitWatches` and `TimerSource` on it. On `Event::Ready`, `dispatch` folds the reports into per-pane flags and blink phases. Taking a flag re-arms its descriptor, so a descriptor that is still ready reports again (level semantics), and readers must not block. An exit watch keeps reporting until `unregister`, which covers an early `NOTE_EXIT`.

On macOS, `macos::login` picks the login shell: the requester's `SHELL` if it is an absolute path to an executable file, else the account's shell from the user database (nix `User::from_uid`); with neither, `prepare` fails before the window. Unless the requester set `LC_ALL`, which is kept as is, the child gets `LC_CTYPE=en_US.UTF-8` when its character locale (`LC_CTYPE`, else `LANG`) is not a UTF-8 locale with an `LC_CTYPE` table under `/usr/share/locale`; `C` and `POSIX` count as not UTF-8, because the terminal speaks UTF-8. Everything else, including agent sockets, passes through unchanged.

On macOS, settings load and watching run in a child process, so a FIFO or stalled include cannot block the main thread. `macos::reload` starts this executable with `--internal-config-watch`; the child's stdin is one end of a socket pair. The child runs `sumie-config::Watch` (vnode kqueue, includes, 100 ms debounce) and writes each result as a frame from `reload::frame`: a 4-byte big-endian body length, a version byte, a kind byte, then resolved settings as JSON (`Config::to_json`) or a located diagnostic. Bodies are capped at 1 MiB; the decoder checks the version, kind and cap before it reserves a body, accepts input split anywhere, and applies only whole frames. The app registers its socket and the child's `NOTE_EXIT` descriptor (`sumie-macos::exit::ExitWatch`) with `Watches::register_config` and drains at most 2 MiB per wake. It does not wait for the first result. The terminal driver and the test page start from the defaults under the banner if that result is a diagnostic. The test page presents nothing until the result arrives. The terminal driver waits at most 500 ms, about five times its blank window on a normal start, then starts from the defaults under `settings still loading: <path>`; the result applies through the hot-reload path when it arrives. Later diagnostics keep the active settings; any later settings, even identical ones, remove the banner. An oversized, malformed or truncated frame, or EOF or the child's exit while running, is a watcher fault (an exit report does not wait for EOF, which an inherited copy of the socket can delay): the app drops the partial frame, shows the fault in the banner, keeps the settings and stops the child. To stop it, the app closes its socket and stops watching it; a thread in the child exits on that EOF even while `load()` blocks, and SIGKILL follows 500 ms later. The app reaps the child on exit readiness with `try_wait` and never waits or joins; `Drop` sends SIGKILL without reaping. Closing the terminal window or the test page closes the watcher; the app exits once it is reaped (the terminal driver also waits for closing pane children). If the app exits without closing (the watchdog, or a system quit's reply with children left), the child exits on EOF and launchd reaps it. The test page drives its 600 ms cursor blink from a `Watches` timer.

On macOS, `sumie-macos::pasteboard` reads and writes the pasteboard's string through `objc2-app-kit`'s safe `NSPasteboard` API. Only a helper child calls it: a read waits for a lazy provider's promised data, and `AppKit` gives up on a provider that never answers only after about two minutes. `macos::pasteboard` serves `WindowOps::read_clipboard`, `write_clipboard` and `write_terminal_clipboard`. Each request starts this executable with `--internal-pasteboard`, its stdin one end of a socket pair; the app writes one request frame (`reload::frame`) without blocking and reads one reply on the readiness bridge. Requests run one at a time in the order they were made, with at most 16 waiting, so a paste after a copy reads the copy; a paste for a recipient that already has one in flight or waiting joins it. A child without a reply 5 s after it started is cancelled like the configuration child: the app closes its socket, the child exits on that EOF even while the board blocks it, SIGKILL follows 500 ms later, and the app reaps it on exit readiness with `try_wait`. A read delivers a non-empty string of at most 1 MiB as `Event::ClipboardText` with its request's recipient generation, so the shared session drops it when that recipient is gone, and the pane enqueues the framed paste whole or not at all; a longer string sends nothing, and a copy over 1 MiB leaves the board unchanged. A copy builds its item before it clears the board and then writes it in one call; the API has no atomic replace, so a write the server refuses after the clear leaves the board empty. A terminal's OSC 52 write or clear applies only while the window is key; the VT still denies reads. Draining cancels every request and reaps the children before exit. Release builds serve the general board. With `macos-ci`, the helper child serves only the board `SUMIE_MACOS_CI_PASTEBOARD` names and refuses the request when it is unset or empty; `Board::named` rejects the general board's own name. Cmd+C and Cmd+V reach the shared copy and paste actions; Ctrl+Shift+C and Ctrl+Shift+V reach the program, and a drag release does not copy.

## Terminal core (`sumie-vt`)

`Terminal` owns one libghostty-vt terminal, one render state, and their row and cell iterators. Its handles are `!Send` and `!Sync`: this API keeps the terminal on its owner thread. Writes, resizes, and snapshots require an exclusive borrow. A snapshot copies the viewport into Rust-owned rows, with one entry per column and width zero on a wide glyph's trailing cell. It includes resolved foreground and background colors and the viewport cursor. No native handles or borrowed pixels are stored in the snapshot.

The VT `style` module decodes SGR flags and copies the active palette only when a cell has an indexed underline color. Otherwise, the snapshot reads ANSI palette entry 3 directly for the tab strip accent. The snapshot marks visible OSC 8 cells independently of their SGR underline and does not copy their URLs.

The VT `cursor` module configures libghostty-vt's cursor defaults and reads the effective shape and blink mode from the render state. Ghostty preserves explicit DECSCUSR overrides through config reload; DECSCUSR 0 restores the latest defaults.

The VT `effects` module owns the synchronous callback queues. PTY replies and pending decoded clipboard writes each have a 1 MiB limit. The clipboard read callback replies with denial; the write callback replies after admitting a supported write. The title callback copies the latest title. The bell callback sets a flag, the desktop notification callback copies up to eight requests (control characters removed, title 256 and body 4096 bytes) and the OSC 9;4 callback keeps the latest report. None of these callbacks call platform code or log payloads. PTY output readiness wakes the owner thread before feeding VT, so that same dispatch can drain effects without a second wakeup. VT 1.0.1 parses CSI 22/23 but ignores those actions in its C terminal handler.

Bells, desktop notifications and progress reports reach the main thread as `sumie_vt::Event`s. `app::notices` decides what they do. A bell marks a tab that is not active like background output. A progress report belongs to its pane; a tab shows its focused pane's report, else the first other pane's, along its top edge in the strip. A notification is dropped when its pane is on screen in a focused window; otherwise `sumie_core::notify::Gate` admits one per second, and the same text not again within five seconds (the clock is passed in, so tests use a fake one). `WindowOps::notify` hands an admitted request to the platform. On Linux, `linux::notify` owns the only worker thread outside PTY readers: connecting, authenticating and sending on the session bus block, so the main thread only `try_send`s into a four-slot queue and drops on overflow. The worker speaks the few D-Bus messages needed (EXTERNAL authentication, `Hello`, `org.freedesktop.Notifications.Notify`) over the address in `DBUS_SESSION_BUS_ADDRESS`, falling back to `$XDG_RUNTIME_DIR/bus`; it never starts a bus and links no D-Bus crate. macOS will implement the same trait method with `UNUserNotificationCenter`.

Before PTY spawn, `pane` sets the VT identity from the child environment. The VT `identity` module configures Ghostty's query replies on the terminal owner thread; it does not read the environment or install terminfo. It passes the name to Ghostty for XTGETTCAP `TN` and serves the static application version through the XTVERSION callback. XTGETTCAP `RGB` comes from Ghostty's fixed query table, not the bundled terminfo source.

The VT `reports` module answers XTWINOPS size queries (CSI 14/16/18/19 t) from the grid and the cell size last passed to `resize_pixels`, with no reply before a cell size exists, and the color-scheme query (CSI ? 996 n) from the current background, so an OSC 11 change moves it; the scheme is light where the drawn chrome picks its light palette. The build patches Ghostty's legacy key encoding to match xterm: a modified Enter is CR (ESC CR with Alt) unless modifyOtherKeys state 2 is set; Ctrl+[, Ctrl+I and Ctrl+M send ESC, Tab and CR; and Ctrl+Shift+<letter> sends the letter's C0 byte. Under modifyOtherKeys state 2, a Ctrl key without text is encoded as CSI 27 from the key's character, uppercased by Shift. Kitty keyboard flags keep Ghostty's encoding.

The VT `selection` module uses libghostty-vt's word and line helpers. A Zig bridge maps the pinned Ghostty link pattern back to cells in one logical line, including soft wraps. Word selection accepts both URLs and paths; hover accepts only URIs from core's scheme allowlist. OSC 8 takes precedence: an implicit link spans adjacent cells, while an explicit ID groups all visible runs with the same ID and URI. Native references remain inside the call. The formatter joins soft wraps and includes selected rows outside the viewport.

`build.rs` fetches the Ghostty archive by commit and checks its SHA-256 before extracting it under Cargo's `OUT_DIR`. Zig uses its package cache on repeat builds. For a clean offline build, set `SUMIE_GHOSTTY_ARCHIVE` to the prefetched archive and `GHOSTTY_ZIG_SYSTEM_DIR` to the directory of unpacked, hash-named Zig packages. The private FFI module vendors the declarations it uses from the libghostty-rs revision for vt-1.0.1, without taking on its separate native build.

Before compiling the extracted source, the build script links `src/search/grid.zig` into the pinned Ghostty module and enables uucode's simple-fold table. The bridge uses Ghostty's page types directly; Rust does not depend on Ghostty's internal cell layout.

`sumie-core::graphics` carries image revisions, pixel formats and viewport-relative placement geometry. Ghostty owns protocol parsing, replies, image IDs, pixels, cursor movement and grid anchors. On a texture cache miss, the renderer requests the exact revision through the pane's `ImageSource`. The VT checks the revision before lending its pixels; the immutable borrow prevents a write, tick or resize during upload. A protocol acknowledgement confirms storage, not GPU residency. On Linux, file transfers accept only regular files on memory filesystems below `/tmp` or `/dev/shm`. Reads and Wuffs PNG decoding still run synchronously on the terminal owner thread.

`app::animation` uses one monotonic clock for the window. After applying pending geometry, the app refreshes the visible pane snapshots. Only placements from the current snapshot that the renderer actually presented, and the source of a presented viewer, can contribute a deadline. A one-shot calloop timer wakes dispatch at the earliest deadline; the compositor's frame slot still gates presentation. Suspended windows, surface retries and hidden tabs do not tick. Thumbnails and viewers follow the current pixel revision. The viewer identifies its source by image transmission and placement revision, not frame number.

If an image already has animation frames when placed, its natural size is preserved. Adding frames after placement does not change the thumbnail geometry or move the cursor.

Some video clients stack anonymous RGB placements rather than replacing a named image. The renderer skips a lower placement only after it admits an opaque cover of the same footprint. If the cover does not fit the GPU budget, the lower placement remains eligible. Ghostty still owns the covered placements and can reveal them after a delete. Its native image storage has a 320 MiB budget independent of the GPU cache.

The Kitty placement bridge caps natural-size inline images before Ghostty stores the placement and advances the cursor. It sets only the row count, so Ghostty computes the column span from the source aspect ratio. The alternate screen, suppressed cursor movement (`C=1`), relative placements (`P`/`Q`), Unicode placeholders (`U=1`) and explicit row or column requests bypass the cap. `timg --grid` uses ordinary primary-screen placements but assumes natural sizes when it moves the cursor; use `images.thumbnail-rows = 0` to preserve its layout. Changing the setting affects new placements only.

`app::viewer` routes clicks and keyboard input for pane-local viewers. A click must begin and end on the same presented thumbnail without a drag. `view::images` fits the source rectangle to the pane and publishes thumbnail hit targets only after presentation. The renderer reserves the viewer's existing texture before admitting ordinary images and clips its backdrop to the pane. A viewer takes keyboard input only after presentation and closes when the VT removes its placement or the renderer cannot show it.

`sumie-render::images::quad` retains the unclipped edges of a thumbnail for the image shader. The one-device-pixel border and hover icon share the image's clipping and z-order; an edge clipped by scrolling does not become a new border. The view supplies Astryx colors. Ordinary placements and the enlarged viewer have no border or icon.

## Font pipeline (`sumie-font`)

`FontSystem` owns font discovery, loaded faces, shaping and rasterization scratch space, and one CPU atlas. Linux uses `fontconfig` for family aliases and locale-aware charset matches. On macOS, Core Text selects the primary font by name. The font file's PostScript names identify faces within collections. If the preferred fallback cannot be loaded or has no usable outline for the character (for example, an `hvgl`-only face), discovery tries Core Text's default cascade in order. Last Resort placeholders do not count as coverage. After the cascade, discovery tries every installed face whose character set contains the character: families in cascade order (the user's language order) first and absent families last, then nearest the requested bold and italic, then by PostScript name. Noncharacters, code points Core Foundation marks unassigned, and private use skip this system-wide step: no font draws the first two, and private-use glyphs come only from the configured font or the cascade. Core Text's query has no time limit, so the step runs on one worker thread per `FontSystem`, and a lookup waits for it at most 50 ms, or not at all while an earlier lookup is still running. A character without an answer draws as missing; the next lookup after the answer arrives, when the cell is drawn again, takes it. If no face is usable, the missing-glyph error lists each rejected font with its path and reason. `FontSystem` remembers each character and style that fallback could not serve (but not a pending lookup) until the font, its settings or the scale change, so only the first error carries the list. Font discovery and the first use of a fallback face can block on file I/O.

The caller supplies the grid widths for an already ordered, left-to-right run, including zero-width continuations. The font crate does not infer widths from Unicode or consult terminal state. HarfRust shapes face runs with `calt` and `liga`; glyph advances inside a cluster do not change its grid span. Wide clusters center their shaped advance in two cells. Each fallback face starts at the primary ppem and scales down if its representative CJK advance exceeds two cells or its typographic line exceeds the cell height. The same line metrics set the face baseline. Oversized ink shrinks to fit and is centered horizontally.

The `sprite` module draws box lines, block elements and Powerline separators (U+2500–259F and U+E0B0–E0BF) before font lookup. Its atlas keys use a reserved face ID. Each mask starts at the cell origin and occupies exactly one device-pixel cell, independent of the font baseline. Light strokes are `max(1, round(cell_height / 16))` pixels thick; heavy strokes are twice that. Sprites use the same R8 atlas and 1:1 sampling as font outlines.

The `decoration` module draws underline, strikethrough and overline masks into the same atlas. Masks use the primary face's device-pixel metrics and stay inside the row. The view reuses one mask per decoration style per frame. Decorated spaces draw ink; the spacer left at the end of a row when a wide glyph wraps does not. Only a change of face style, foreground or selection splits the shaping run.

Skrifa draws outlines into Zeno's 8-bit coverage rasterizer. `FontOptions` fixes the hinting mode for one font system. The default mode leaves outlines unhinted. Enabled modes cache a hinter per face and raster size without changing grid metrics or shaping advances. An optional CSS weight applies to primary and fallback matches and overrides each face's `wght` coordinate if present.

Styled runs keep the primary grid. The font system resolves a bold or italic face on first use, including for fallback characters. Bold requests weight 700 by default, or the configured weight plus 300 up to 900. If the result is no heavier than the non-bold face, the rasterizer strokes the outline. It shears the outline when the requested italic style is missing. Each style has its own face identity in the atlas.

Glyph origins and cell metrics use integer device pixels. Atlas entries retain their pixel rectangles when the shelf packer grows; growth marks the full atlas dirty. At a new scale or font size, replace the `FontSystem` and its atlas together. The binary reads the atlas dimensions, bytes, and dirty rectangles, then clears the dirty regions after consuming them. The font crate does not call the GPU.

## GPU renderer (`sumie-render`)

The caller owns the process-wide wgpu instance, adapter, and device and passes device and queue handles to the renderer. `backends()` selects `PRIMARY` (Vulkan on Linux, Metal on macOS); on Linux set `SUMIE_GPU_BACKEND=gl` to select the GLES backend instead. Pass that selection and the caller's instance descriptor to `instance_descriptor()`. It preserves the display handle required by GLES on Wayland and disables only indirect command validation on GL, where wgpu's internal compute pipeline can fail device creation. The renderer issues no indirect commands. `sumie-render` does not create native windows or depend on `sumie-font`.

`AtlasUpload` borrows a tightly packed R8 coverage atlas and dirty rectangles. Upload the full atlas on the first call or when its dimensions change; otherwise upload only dirty regions. `DrawList` borrows row-major cell backgrounds and glyph quads. Input colors are straight sRGB RGBA8. Geometry uses integer device pixels, and each glyph's atlas and destination rectangles have the same size. A glyph names its owning cell for contrast and coverage correction, including when its ink overhangs that cell.

The renderer uploads instances through a reusable staging belt and draws backgrounds, glyphs, and the optional cursor in that order in one render pass. The shader adjusts glyph contrast toward the configured minimum (default 1.1) by moving its RGB toward black or white. Following Ghostty, it corrects grayscale coverage so the resulting luminance matches an sRGB interpolation, then blends premultiplied colors in linear light into an sRGB attachment. wgpu supplies the transient command encoder and acquired surface image each frame. The pipeline persists, and draw buffers and bindings change only when capacity or atlas dimensions change.

Translucent frames replace the underlying color at each default background rather than blending the pane and cell twice. Inactive pane tints and split dividers preserve background alpha. `renderer::presentation` owns the reusable color attachment and converts linear premultiplied composition to the surface's straight or premultiplied sRGB representation. It does not read config or call Wayland. Opaque frames render directly to the surface.

On the render thread, call `upload_atlas` and `draw` only after releasing the terminal lock. The caller schedules frames; the renderer never draws or presents on its own. `Renderer` draws to a reusable offscreen target. `SurfaceRenderer` owns a caller-created surface, configures it at nonzero device-pixel sizes, and presents once per successful draw. `resize` may wait for swapchain GPU work. Drop `SurfaceRenderer` on the render thread; its renderer resources drop before its surface.

The renderer caches image textures separately from glyph atlases. The cache charges at least 64 KiB per texture and caps residency at 320 MiB and 4096 textures. It evicts off-screen textures first, in least-recently-used order. A frame draws images in Kitty z-order relative to cell backgrounds and glyphs, clipped to the terminal grid before drawing window chrome. GPU eviction does not delete a protocol image: a later visible placement can upload it again from its pane's image source.

On a cache miss, the renderer can overwrite a texture of the same dimensions, retaining its bind group. It reserves viewer textures first and never overwrites a texture already admitted to the current frame. It prefers to recycle off-screen revisions over pending candidates. An opaque inline placement can hide a lower placement of the same z-index and clipped bounds only after its own upload succeeds. `images::upload` copies RGBA pixels unchanged. RGB, gray and gray-alpha bytes go unchanged into an `R32Uint` scratch texture, kept between frames only while it is at most 64 MiB and used within the last 120 frames, and `images::expand` writes their RGBA texels in a render pass, so the main thread never touches individual pixels; each image in one submission takes its own scratch rows. Image textures are `Rgba8Unorm` holding sRGB bytes, which the image shader decodes after loading.

The workspace tests use the same pixel checks on the selected backend and on Linux GLES. Set `SUMIE_REQUIRE_GPU=1` to fail instead of skipping when an adapter is unavailable. Set `SUMIE_RENDER_ARTIFACT_DIR` to an existing directory to save `grid.png` from the selected backend test.

The cursor bar and underline use the same device-pixel thickness as a light box line: `max(1, round(cell_height / 16))`. The hollow block uses one device pixel per edge.

## Unix PTY (`sumie-pty`)

`Pty` owns the Unix master, child process group, and one reader thread. It does not own terminal state, windows, rendering, or an event loop. `SpawnOptions` supplies the command or login shell, the complete child environment (including `TERM` and `COLORTERM`), the initial cell and pixel dimensions, and a close grace period. The default grace period is three seconds, with a five-second maximum. Spawn can wait for exec; the live-pane methods do not wait for PTY I/O or child exit.

`sumie-pty::spawn` serialises descriptor creation with process creation. A descriptor created without `O_CLOEXEC` exists briefly without `FD_CLOEXEC`, and a `fork` on another thread would copy it into a child that keeps it across `exec`. `pty-process` opens the PTY master that way on both platforms; Darwin also has no `pipe2` or `SOCK_CLOEXEC`, so its wake pipes and socket pairs are created that way too, while Linux uses `eventfd` and `socketpair` with `CLOEXEC`. Such a creation holds a process-wide lock shared (`Pty::spawn`, the macOS wake pipe, `socket_pair` on macOS); every spawn (`Pty::spawn`, `sumie_pty::spawn` for the config child and `tic`) holds it exclusively. `open` with `O_CLOEXEC`, `F_DUPFD_CLOEXEC` (the readiness bridge's duplicates) and `kqueue` are atomic: XNU creates a kqueue close-on-exec and close-on-fork and never copies one into a child, even with `FD_CLOEXEC` cleared. The link opener's `posix_spawn` names its child's descriptors. A macOS test execs a zsh login shell (Apple's bash 3.2 closes inherited descriptors as a login shell, so it would hide a leak) while the bridge, a pane and the config child exist, and requires that the shell's `lsof -nP -p $$` shares no descriptor identity (pipe or socket object, device and inode) with the test process.

The reader polls the master and a stop descriptor. It sends byte chunks through a bounded channel and signals `output_fd()` with an eventfd on Linux or a pipe on macOS. A macOS master read returns at most 1 KiB, and each child write reaches the reader on its own. A child that writes one line at a time (BSD `head` on a tty) is therefore bound by its own write rate, about 2.8 MB/s with any reader. The reader neither waits for more nor batches reads, because neither raises that rate. On readiness, clear the wake with `clear_output_wake()` before calling `try_recv_output()`. The app drains at most `OUTPUT_SLOTS + 1` chunks per pane per dispatch. That covers the whole queue at wake time and leaves other tabs responsive to input; later sends signal the descriptor again. `enqueue_input()` admits whole messages into a 1 MiB FIFO. Poll `input_fd()` only while it is present and call `flush_input()` on write readiness; partial writes keep their original order. A closed peer returns `false` from `flush_input()` and the app closes the pane. `resize()` applies `TIOCSWINSZ`.

Keep the `Pty` after removing the pane from the UI. `close()` sends SIGHUP to the child group, discards queued I/O, and signals the reader to release the master. Call `service_child()` on `exit_fd()` readiness or at `close_deadline()`. It reaps a ready child or sends SIGKILL once at the deadline, then keeps watching until exit. The absence of `exit_fd()` marks completion even when no status is available because the child was already reaped. No other code may wait on the child or enable automatic reaping. `Drop` never joins or waits for the child; it hands any unreaped child to the reader thread for the same deadline and exit handling.

Linux uses rustix for pidfd, `waitid(P_PIDFD)`, and Unix descriptor operations. macOS uses nix for the safe kqueue API and rustix for `waitpid` after `EVFILT_PROC` reports `NOTE_EXIT`. `NOTE_EXIT` can arrive before the child is waitable, and the one-shot proc filter cannot be added again to an exiting process. Each such early report therefore arms a one-shot 1 ms kqueue timer, so `exit_fd()` reports again until the child is reaped. `pty-process` supplies safe Unix PTY allocation and controlling-terminal spawn through its synchronous API; its Tokio feature is disabled.

## Wayland platform (`sumie-wayland`)

`Platform::connect` creates one xdg-toplevel with app ID `sumie` and registers its private Wayland queue in a calloop event loop. Connection setup performs a registry round trip. The caller dispatches and drains events on the same thread and registers non-Wayland sources with `Platform::loop_handle()`. The window requests server-side decorations. If the compositor does not grant them, P0 is undecorated and logs the fallback once.

`platform::dispatch` waits on calloop and transfers one batch of Wayland events at a time. Events generated by the response to that batch wait until the next turn.

Wait for `Resized` before sizing the renderer. `scale` is in units of 1/120. With fractional-scale-v1 and viewporter, the surface keeps `buffer_scale = 1`; its viewport destination is the logical size, and device dimensions round `logical × scale / 120`. Otherwise SCTK supplies the integer scale from `wl_surface.preferred_buffer_scale` or the outputs. Call `begin_frame()` immediately before committing a ready buffer. The initial configure and each completed frame callback release one frame slot; neither forces a redraw. Finish that buffer commit before changing IME state or dispatching again.

`platform::background_effects` owns opaque and blur regions in surface-local logical coordinates. On the event-loop thread, `Platform::set_background_effects` stages the latest settings and reports whether they change surface hints. It does not block, schedule a frame, or commit the surface. The next buffer commit applies them with its geometry. The adapter requests blur only for translucent surfaces and only when `ext-background-effect-v1` advertises the blur capability. Without it, transparency still works. The module does not choose window colors or render them.

The GPU and Wayland adapters use the same rounded eight-bit background alpha as the cells. Alpha 255 keeps the opaque surface and region. A compositor capability change requests a frame only when the requested blur differs from the effect on the surface.

SCTK and calloop supply window, seat, and XKB dispatch and key repeat. `wayland-protocols` supplies the fractional-scale, viewporter, and text-input-v3 bindings. The adapter uses the first available keyboard seat and emits raw evdev codes and interpreted key data without matching shortcuts. The text-input object emits committed text before the next preedit at `done`. Switching between search and the PTY starts a new input generation; the adapter discards batches from before the current enable serial. Within one generation, a stale serial applies the batch but defers outgoing cursor changes until a matching `done`. The adapter resends the rectangle after focus returns, but does not resend an unchanged rectangle within a focus session. Text-input interface version 2 pairs its state commit with a surface commit.

`Platform::window_owner()` shares the SCTK window and its display connection with wgpu. The window owner supplies borrowed raw-window-handle traits and exposes no Wayland proxy. `Platform::display_handle_source()` retains only the connection for wgpu instance creation, including on GLES. SCTK destroys the xdg-toplevel, xdg-surface, and wl_surface in order after the last window owner drops. `cargo run -p sumie-wayland --example window` demonstrates `present_shm` and logs event metadata without input contents.

## Gates

Run `scripts/check-all.sh` from the repository root. It runs the read-only checks, then the negative controls. Use `--fast` to run only the read-only checks. Negative controls temporarily edit files and restore their bytes. They also compare Git porcelain status before and after. Do not edit the worktree while they run. Cargo uses `$CARGO_TARGET_DIR` if set, otherwise a `sumie/target` directory under the user's cache.

- Dependencies: inspect declarations in `cargo metadata`, including renamed, build, dev, and target-specific dependencies, regardless of the current platform.
- Workspace membership: every immediate directory under `crates/` must be a workspace member, and every member other than the root package belongs directly under `crates/`.
- Unsafe code: every Rust target root declares unconditional `#![forbid(unsafe_code)]`, except in `sumie-vt`, `sumie-font`, `sumie-render`, and `sumie-wayland`. In `sumie-wayland`, unsafe is limited to raw-window-handle trait implementations. Clippy denies undocumented unsafe blocks. `sumie-macos` is not exempt.
- File length and names: cap Rust sources and gate scripts at 600 physical lines. Reject reserved module and crate names (`util`, `common`, `helper`, `misc`). The module check is lexical: it checks source paths and `mod` declarations, ignores comments and literals, and does not expand macros.
- Lint policy: each manifest inherits workspace lints. Only the root `clippy.toml` is allowed. `allow` and `expect` cannot suppress `warnings`, `clippy::all`, `clippy::pedantic`, `clippy::too_many_lines`, `clippy::cognitive_complexity`, or `clippy::undocumented_unsafe_blocks`, including inside `cfg_attr`.
- Patches: every git entry under `[patch]` in the root manifest pins a full 40-hex `rev` that `Cargo.lock` records, never a `branch` or `tag`. Added lines in `third_party/**/*.patch` contain no `eprintln!`, `println!` or `dbg!`.
- Terminal identity: require `Tc`, `Smulx`, `Setulc`, `Ms`, `Sync`, and `Hls` in the bundled terminfo source. Reject `RGB`, which is query-only.
- Shell integration: each script emits prompt marks (OSC 133 A–D with the status), the SSH wrapper and OSC 7. The bash script and `cwd.sh` contain no `[[ -v` outside comments, since macOS ships Bash 3.2. On macOS, `macos::login` tests run real `/bin/bash` 3.2 and `/bin/zsh` login shells in their own test process with an isolated `HOME`, `ZDOTDIR` and data directory.
- Rust checks: check formatting, run Clippy with warnings denied (including an 80-line function limit and a cognitive complexity limit of 15), and require at least one passing workspace test. On macOS, `clippy-macos-ci` also lints with `--features macos-ci`. Gate scripts require Python 3.11 or newer.
- Pasteboard (macOS): `macos-pasteboard` runs `scripts/macos/pasteboard.py` against the terminal runner with `SUMIE_MACOS_CI_PASTEBOARD` naming a fresh board, which the check reaches through its own `pbfixture.m`; it posts Cmd+V and Cmd+C as real `CGEvent` keys and records the PTY with `keyrec.py`. Paste: the string arrives as is, and framed once in mode 2004. Empty: no string or an empty one sends nothing, and the next paste arrives. Oversized: 1 MiB + 1 sends nothing, a string whose framing makes 1 MiB + 1 sends nothing, and one that fills the FIFO exactly arrives whole. Stale: a provider that answers, on the check's signal, after search opened and closed and after a key typed behind the next paste reached the shell sends nothing, and that next paste, promised with other contents, arrives once and alone. Stalled: a provider that never answers sends nothing, pings stay within 100 ms, no helper is left 6.2 s after the request, and a later paste arrives. Copy: a mouse drag over a row (runner `mouse`, a queued `NSEvent`) leaves the sentinel at its release, and Cmd+C replaces it with the dragged cells. OSC 52: a focused write and clear apply, an unfocused write does not, and a query gets no contents. The general board's change count must not move; the check never reads it. Controls: stamp a paste with the current generation, send a paste unframed when the framed one does not fit, no helper timeout, an OSC 52 write without focus, and copy on a drag release. No check serves the general board: the board choice is the pure `select_board`, and its control, which returns the general board, fails a unit test in `test`, as does a control that starts a helper for every repeated paste.
- Frame slot (macOS): `macos-resize`, `macos-idle`, `macos-flood`, `macos-timeout`, `macos-throughput` and `macos-loading` run `scripts/macos/frames.py` against the terminal runner. The runner uses cursor blink off and `/bin/sh`, and `frame-hook.m` is injected: it times `nextDrawable`, can return nil drawables, and can hold one wgpu submission on an `MTLSharedEvent`. The configure counters that the resize check reads exist only with `macos-ci`. Resize: during a CG drag with the GPU held, no configure runs on a non-empty queue and pings stay within 100 ms; the control configures on `Resized`. Idle: no present in 60 s, except right after a focus, occlusion or size change; the control presents every turn. Flood: continuous `seq` output, then short bursts from idle: at most one present per refresh and a median acquire of at most 2 ms. A composited layer releases drawables once per refresh, so in continuous output the display throttles any slot; a burst from idle finds free drawables, and there the control, which frees the slot on every wake, presents back to back and fails the pacing limit. Timeout: after two nil drawables, no acquire for 1 s and then 2 s, with pings within 100 ms; the control caps the back-off at 50 ms. Throughput: `head -c 64M /dev/zero | base64` through the pane reaches 20 MB/s; the control reads the PTY 8 bytes at a time. Loading: with an include that is a FIFO without a writer, the window presents the defaults under the loading banner within 1 s; once a file replaces the FIFO, the settings apply and the banner clears. The control has no first-result deadline. A runner `report` before the first result waits up to 5 s for the session. With `SUMIE_TIMING=record`, as on hosted runners, ping, acquire-time, throughput and blank-time limits are only reported, and the throughput control, whose marker is a rate, does not run.
- Keyboard (macOS): `macos-keys` runs `scripts/macos/keys.py` against the terminal runner. `keyrec.py` runs in the runner's shell, sets its modes, waits for a cursor position report, and writes the bytes that reach the PTY as hex to a file; the runner posts real `CGEvent` keys to its own PID (`key`), except repeats, which the window server drops when posted to a PID, so the runner queues them in `AppKit` as `NSEvent`s made from the same `CGEvent` and moves key status to a decoy window and back (`blur`, `focus`). Plain: a, Enter, Tab, Backspace, Left and Ctrl+C give `61 0d 09 7f 1b5b44 03`, and Cmd+C nothing. DECCKM: Up and Left give `1b4f41 1b4f44`. Kitty (flags 11): a press of a, then focus loss, gives one release; after refocus, a's repeat and release are dropped and b types. Mode 1004: a Shift tap reports nothing; with Shift held, focus loss reports once and refocus once. Command (Kitty flags 11): Command, Cmd+C and Cmd+K send nothing for press, repeat or release, also with Command lifted first; a pressed before Command sends its press and release but not its repeat with Command down, posted once the press reached the PTY. Option: left Option+a and +1 give `1b61 1b31`; right Option, and Option without a side bit, give `c3a5` for a and one layout character without ESC for 1. Links: the runner posts mouse events as queued `NSEvent`s at cell centres (`mouse`); with two URLs on a row, Cmd press and release on one opens it once (the stub reports its length), a Cmd drag along it opens it, while a plain click and a Cmd drag off the link and back open nothing, and no mouse bytes reach the program. Tracking (modes 1002 and 1006): a click gives its SGR press and release, a plain drag reports nothing, and a left Option drag gives press, motion and release without the Alt bit. Without permission to post events the gate fails. Controls: stop forwarding keys (no bytes), report focus on an empty `ModifiersChanged` (two reports for one loss), leak the release of a consumed shortcut, repeat a key held into Command with it, send right Option or Option without a side as Meta, apply the Linux Alt+digit aliases on macOS, open a link released after a drag off it, cancel a Cmd+click that moved along its link, and report a tracking press before it becomes a click or a drag.
- Input methods (macOS): `macos-ime` runs `scripts/macos/ime.py` against the terminal runner with a named board, recording the PTY with `keyrec.py`. Protocol cases (input methods off; the runner injects winit's events with `ime preedit` and `ime commit`, between real `CGEvent` keys) cannot prove a native cancellation: preedit, empty preedit and commit give the commit's bytes once and a second commit nothing, with the overlay's length and caret checked; a commit after a pane switch, and one after search opened, reach no PTY; under Kitty flags 11 a held a gets its release when a composition starts, once, though its real key-up follows; during a composition Cmd+V pastes once, Cmd+C sends nothing and the commit follows. Native cases run when Traditional or Simplified Chinese Pinyin is the selected input source, which the check never changes, and are skipped otherwise (hosted runners): n i Space commits one character without a Return and Escape cancels; a reported 1 gets its release when n composes; Cmd+V and Cmd+C during n i paste once and leave the composition at two bytes; focus loss, a split and opening search each end the native composition, so the next a starts a one-byte one. Controls: let a commit keep its owner (sent twice), rebind the owner to the new generation (late commit in the new pane), skip the takeover release, let routing forward an unpaired release (sent twice), drop the preedit caret, and, under Pinyin only, skip the native cancel; unit tests catch a commit kept across an input-source change and an underline that ignores the selected clause.
- Close and Quit (macOS): `macos-close`, `macos-repeat`, `macos-fatal`, `macos-system`, `macos-stuck` and `macos-exit` run `scripts/macos/lifetime.py`, one fresh terminal runner per case, with `RUST_LOG=debug` and a shell that runs `trap '' HUP; sleep 1000`. Close (`performClose:`): CGWindowList reports the window off screen before the reap; SIGHUP, SIGKILL 3 s later, the reap and its exit watch removal follow in order, and the process exits 0. Repeat: two Quits give one intercept, a veto and one grant, with SIGKILL 3 s after the first. Fatal: an injected error with the child alive, and again during an ordinary Quit: the child is killed and reaped, the exit status is 1 with `sumie: injected fault`, and no grant runs. System: a self-sent quit Apple event with `kAEReallyLogOut` gets `NSTerminateLater` and its reply within 4 s; with the injected error, the error is logged and the reply still comes. Stuck: after Quit, a runner `stall` blocks the main thread: the watchdog exits 70 within 10 s (0 within 6 s after a system quit) and logs the `reaping` stage. Exit: `exit` in the last shell closes the window and exits 0. The controls keep the window on screen until the process exits, drop the SIGKILL at the grace period, reply `NO` to the system quit, and start no watchdog. `macos-cycles` (not in `check-all.sh`) opens and closes the window 200 times in one process (runner `cycle`) and compares descriptors (`lsof`), threads (`ps -M`), zombie children and `vmmap` IOSurface and IOAccelerator regions with the first window; hosted CI records it. `SUMIE_LIFETIME_TRIGGER` (`red`, `cmdq`, `ax`, `dock`) replaces the runner's Close or Quit with a CG click on the close button, Cmd+Q through the HID tap, an AX press on the Quit item or Quit from the Dock item's menu, for runs on the owner's Mac.
- Pane budget (Linux with `kwin_wayland`): `panes` builds the release binary and runs `scripts/perf/stall.sh` for 20 s in a private nested KWin at scale 1.25. Injected chords split the window into 20 panes in pane-ID order; each pane's shell is a writer that prints one changing line every 100 ms and stamps each line. The gate fails if a writer did not advance ("N of 20 panes advanced"), if a pane's line waited more than 200 ms for a frame that snapshotted after it and repainted that pane ("pane N starved"), if a line waited more than 100 ms for the compositor's next visible `presented` ("stall gap over 100 ms"), or if the frame log has no records. It also prints frame CPU p50/p99 and per-stage times. Its controls: a 150 ms busy wait in `Session::draw`, a writer that never prints, a `refresh_visible` that refreshes only the first ten visible panes, and the frame log's present hook removed. `check-all.sh --fast` skips it, and `check-all.sh` and the controls skip it on hosts without KWin, including cloud CI.
- Wake (macOS): `macos-wake` builds with `macos-ci` and runs `SUMIE_MACOS_CI_RUNNER=wake`. From `run_after_handler`, the main thread runs the default, event-tracking and modal-panel modes for 300 ms each. A pipe write 100 ms into each mode must reach the handler, in that mode, within 100 ms. Its control replaces the proxy wake with a default-mode-only `performSelectorOnMainThread:`.

- Pane cycles (Linux): `linux-panes` builds the debug profile and runs `scripts/perf/panes.sh` in a private KWin. After a warm-up it opens and closes a split pane 200 times and a tab 200 times (Ctrl+Shift+E/T, then Ctrl+Shift+W, injected as key chords). Within 6 s of each checkpoint (every 50 cycles) the process must be back to its baseline fd, thread and child counts with no zombie, and RSS must stay within 12 MiB of the baseline and 4 MiB of its first checkpoint. DRM client memory is checked where the driver reports it. A second pane runs `trap '' HUP; sleep 1000` and is closed while a sibling draws; the shell must be reaped within 6 s and no visible `presented` gap may exceed 100 ms (one repeat is allowed). `check-all.sh` runs it on Linux hosts with `kwin_wayland`, after the read-only checks and before the controls, and skips it elsewhere. Cloud CI has no KWin, so only a host run covers it. Its controls leak a descriptor or a thread in `close_pane`, and remove the SIGKILL in `child.rs`.
  An fd count above the baseline reports added and removed descriptor targets with identifying `fdinfo` fields.
  Each checkpoint uses the sample that ends its quiescence wait. The HUP test disables shell job control so a group kill reaches both the shell and `sleep`.

A gate exits `1` for a violation and `2` if it cannot check its inputs. `scripts/install-hooks.sh` sets `core.hooksPath` to `scripts/hooks`. Undo that setting with `git config --local --unset core.hooksPath`; `git commit --no-verify` skips the hook for one commit.

Cloud CI runs the P0 merge gate on Linux x86_64, Linux arm64, and macOS arm64; the macOS leg includes `macos-wake`, `macos-keys`, `macos-pasteboard`, `macos-ime` and the frame-slot gates, recording their timing. The macOS leg also lints and builds the release profile with `macos-ci`, and records `macos-cycles`. A separate `macos-26` job runs `check-gate.py macos-quit` and its three controls: a synchronous grant, a nested run loop with queued winit events, and a system quit answered `Cancel`. The terminal snapshot test checks the wide-cell invariant at the VT boundary; the negative control changes a wide cell's width from two to one.
